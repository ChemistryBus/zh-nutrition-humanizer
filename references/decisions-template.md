# 决策日志模板（写书期用）

> 每次人工判「改 / 留」都记一行。本地文件，建议放 `references/decisions.log`（已 gitignore）。
> 每月汇总一次：同一类判断 ≥3 次才提名进规则表；不到 3 次只观察。

## 一行一条

```
日期 | 章节 | 类型 | 规则/现象 | 决定 | 一句话理由
```

| 字段 | 取值 |
|---|---|
| 日期 | 2026-11-21 |
| 章节 | 1.3 |
| 类型 | 改 / 留 / 新增候选 / 误报 |
| 规则/现象 | L6 而非 / S6 分号 / 新现象：…… |
| 决定 | 改 / 留 / 关规则 |
| 理由 | 作者原话或依据（页码/语料） |

## 示例

```
2026-11-21 | 1.3 | 改 | S6 分号后接"若" | 改句号 | 前句已完整，断句更清楚
2026-11-21 | 1.3 | 留 | L4 分子开关 | 留 | 作者说这是团队固定说法
2026-11-22 | 2.1 | 误报 | T2 而非 | 关 | 引文里的原话，不能改
2026-11-25 | 3.2 | 新增候选 | "由此可见"后接复述 | 观察 | 出现 2 次，等第 3 次
```

## 月度汇总

```bash
# 统计各类决定的次数
awk -F'|' '{gsub(/ /,"",$3); print $3}' references/decisions.log | sort | uniq -c | sort -rn
# 只看看新增候选
grep "新增候选" references/decisions.log
```

汇总后按三条走：

1. **同类「改」≥3 次** → 提名加规则，先在 `references/rule-audit.md` 写一条，再找语料证据；
2. **同类「留」≥3 次** → 给规则加例外（比如引文不改、固定说法不改）；
3. **同类「误报」≥3 次** → 审查规则阈值，必要时降级或关闭。

## 为什么要这个

规则表是从「我猜」变「有依据」的唯一路径：单次判断是噪声，重复三次才是模式。
写书期是最好的采样期——真实稿子、真实判断、真实理由都在手边。
